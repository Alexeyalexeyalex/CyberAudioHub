# CyberAudio Hub



Футуристический веб-плеер в стилистике "Киберпанк" для прослушивания локальных аудиокниг и музыкальных альбомов. Приложение построено на Python с использованием фреймворка Flask и динамически сканирует вашу музыкальную коллекцию при каждом запуске.

## 🚀 Особенности

-   **Автоматическое сканирование:** Просто добавьте новую папку с аудиофайлами — она автоматически появится на главной странице.
-   **Киберпанк-интерфейс:** Современный дизайн в неоновых тонах, вдохновленный стилистикой киберпанка.
-   **Структура по альбомам:** Ваша медиатека организована по альбомам/книгам.
-   **Полнофункциональный плеер:**
    -   Управление воспроизведением (Play/Pause, Next, Previous).
    -   Интерактивный прогресс-бар.
    -   Режим перемешивания (Shuffle).
    -   Отображение плейлиста текущего альбома.
-   **Аккаунты:** Регистрация и вход через локальную базу SQLite. Пароли хранятся только в виде хеша.
-   **Профиль в один клик:** Нажатие на никнейм справа сверху открывает окно, где можно сменить никнейм и пароль, посмотреть список начатых книг и сбросить прогресс по любой из них.
-   **Сохранение прогресса:** Позиция запоминается отдельно для каждой книги, поэтому при переключении между ними воспроизведение продолжается с того места, где вы остановились. У авторизованного пользователя прогресс живёт в базе и доступен с любого устройства, у гостя — в localStorage браузера.
-   **Сколько осталось:** На карточках начатых книг и в самом плеере видно оставшееся время до конца.
-   **Админ-панель:** Отдельная страница `/admin` со всем содержимым базы и управлением учётными записями.
-   **Текстовая версия:** Книгу можно читать параллельно с прослушиванием — текст распознаётся из аудио, а слова подсвечиваются синхронно с озвучкой.
-   **Озвучка книг:** Папку с `pdf`, `docx`, `txt`, `fb2` или `epub` можно превратить в аудиокнигу: текст читает синтезированный голос с интонацией, а книга появляется в медиатеке вместе с синхронным текстом.
-   **Управление с наушников:** Поддержка Media Session API — кнопки гарнитуры, локскрина и системного виджета управляют плеером, а состояние кнопки Play/Pause всегда синхронно с реальным воспроизведением.
-   **Адаптивный дизайн:** Корректно отображается на настольных компьютерах и мобильных устройствах.

## ⚙️ Установка и запуск

Для запуска проекта на вашем компьютере выполните следующие шаги.

### 1. Предварительные требования

Убедитесь, что у вас установлен **Python 3.6** или новее.

### 2. Клонирование репозитория

```bash
git clone https://github.com/your-username/cyber-audio-player.git
cd cyber-audio-player
```
(Если вы не используете Git, просто скачайте и распакуйте архив с проектом).

### 3. Создание виртуального окружения

Рекомендуется использовать виртуальное окружение, чтобы не засорять глобальные пакеты Python.

```bash
# Для Windows
python -m venv venv
venv\Scripts\activate

# Для macOS / Linux
python3 -m venv venv
source venv/bin/activate
```

### 4. Установка зависимостей

Файл `requirements.txt` уже лежит в корне проекта. Установите зависимости командой:

```bash
pip install -r requirements.txt
```

### 5. Добавление контента

-   Перейдите в папку `static/music/`.
-   Создайте подпапку для каждого альбома или аудиокниги (например, `My_Favorite_Album`).
-   Поместите в созданную папку ваши аудиофайлы (`.mp3`, `.m4a`, `.wav`, `.ogg`, `.flac`, `.opus`, `.aac`).
-   (Опционально) Положите в ту же папку изображение для обложки: `cover.jpg`, `cover.png`, `cover.webp` или `folder.jpg`. Обложка показывается целиком, без обрезки — подойдёт любое соотношение сторон.
-   Папки можно вкладывать друг в друга: папка с аудиофайлами внутри считается альбомом/книгой, папка только с подпапками — разделом каталога.

### 6. Запуск сервера

Находясь в корневой папке проекта, выполните команду:

```bash
python app.py
```

Сервер будет запущен. Вы увидите в терминале сообщение, похожее на это:
`* Running on http://127.0.0.1:2077`

### 7. Откройте приложение

Откройте ваш браузер и перейдите по адресу **[http://localhost:2077](http://localhost:2077)** (порт задаётся константой `APP_PORT` в `app.py`).

## 👤 Аккаунты и база данных

При первом запуске рядом с `app.py` создаётся папка `data/` с файлом `cyberaudio.db` — это обычная база SQLite, никакого отдельного сервера БД поднимать не нужно.

### Что в ней хранится

| Таблица    | Содержимое                                                                 |
|------------|----------------------------------------------------------------------------|
| `users`    | Логин (уникальный, регистр не важен), никнейм, **хеш** пароля и признак админа |
| `progress` | По строке на пару «пользователь + книга»: глава и секунда, где остановились |
| `albums`   | Длительности глав — общий кэш, из него считается «сколько осталось»         |
| `transcripts` | Статус распознавания текста по каждой книге                             |
| `transcript_tracks` | Текст главы со временем каждого слова                             |
| `meta`     | Ключ подписи сессий, чтобы вход не слетал после перезапуска сервера         |

Пароли в открытом виде не сохраняются: используется `werkzeug.security` с солью.

### Как это работает

-   Логин задаётся при регистрации и больше не меняется — он же служит адресом профиля (`@login`).
-   Никнейм по умолчанию совпадает с логином. Изменить его можно в окне профиля; если стереть поле и сохранить, никнейм вернётся к логину.
-   Длительности глав вычисляет браузер при первом открытии книги и отправляет на сервер. Поэтому в самый первый раз строка «осталось» появляется с небольшой задержкой, а дальше берётся из кэша.

### Сброс

Чтобы удалить всех пользователей и весь прогресс, достаточно удалить папку `data/`. Она пересоздастся при следующем запуске.

## 🛡 Админ-панель

При первом запуске создаётся учётная запись администратора:

| Логин   | Пароль      |
|---------|-------------|
| `admin` | `123Alex12` |

Войдите под ней — и после входа откроется страница `/admin`. Позже туда можно вернуться через окно профиля (кнопка «Админ-панель») или по прямому адресу.

### Что там есть

-   **Статистика:** число пользователей, администраторов, записей прогресса и книг в кэше.
-   **Учётные записи** — полный CRUD: добавление, редактирование (логин, никнейм, пароль, роль) и удаление вместе с прогрессом.
-   **Прогресс прослушивания** всех пользователей с возможностью сбросить любую запись.
-   **Кэш длительностей** с пометкой, существует ли книга ещё на диске, и кнопкой очистки.

Пароли не показываются даже администратору: в базе лежит только хеш, в таблице выводится название алгоритма.

### Защита от самоблокировки

Панель не даст остаться без доступа: нельзя удалить учётную запись, под которой вы вошли, снять права администратора с самого себя или разжаловать последнего администратора. Для обычного пользователя и гостя страница `/admin` отвечает 404 — так о её существовании не узнать.

### ⚠️ О пароле по умолчанию

Пароль `123Alex12` лежит в исходниках, то есть известен всем, у кого есть доступ к коду. Пока приложение работает только на вашем компьютере, это не проблема. Но если открываете доступ по сети:

1.  Смените пароль в окне профиля сразу после первого входа, **либо**
2.  задайте свои значения через переменные окружения до первого запуска:

```bash
export CYBERAUDIO_ADMIN_LOGIN=my_admin
export CYBERAUDIO_ADMIN_PASSWORD='длинный-случайный-пароль'
python app.py
```

Пока пароль остаётся стандартным, на странице висит предупреждение — оно исчезнет само после смены. Если учётная запись с таким логином уже существует, её пароль не перезаписывается: ей просто выдаются права администратора.

## 📖 Текстовая версия книги

Книгу можно не только слушать, но и читать — текст распознаётся из самой аудиозаписи, а во время воспроизведения подсвечивается произносимое слово.

### Как включить

1.  Войдите администратором и откройте `/admin`.
2.  В таблице **«Текстовые версии книг»** поставьте переключатель у нужной книги.
3.  Дождитесь статуса «готов». Прогресс виден в колонке «Готово глав» и обновляется сам.

После этого в плеере появляется кнопка <kbd>Текст</kbd>. Она переключает страницу в режим чтения: сверху остаётся компактный плеер, ниже — текст главы.

Читать можно, не дожидаясь всей книги: главы становятся доступны по мере распознавания. У книг с готовым текстом на карточке в медиатеке появляется значок с текстовыми строками.

#### Чтение всей книги подряд

Галочка «Вся книга» слева от «Следить за текстом» показывает текст всей книги сразу, с заголовками глав, а не по одной главе. Клик по любому слову переключает аудио на нужную главу и встаёт на это место — то есть по тексту можно перемещаться как по книге, а звук подхватывается сам.

Подсветка при этом идёт по словам той главы, что звучит сейчас: время внутри каждой главы отсчитывается от нуля, поэтому искать слово по всей книге разом было бы неверно. Выбор режима запоминается и восстанавливается при следующем заходе.

#### Если подсветка спешит или отстаёт

Тайминги слов распознавание расставляет по своему внутреннему выравниванию, и они приблизительные — обычно чуть опережают речь. Поэтому в текстовом режиме есть подстройка: кнопки `−` и `+` рядом с галочкой сдвигают подсветку шагом в четверть секунды, а клик по самому значению возвращает ноль. Сдвиг запоминается отдельно для каждой книги, так что настроить его достаточно один раз.

Если промах большой и растёт к концу главы, дело обычно в пакетном режиме распознавания: он режет запись на куски по паузам, и границы кусков смещают тайминги. Поставьте в `worker/config.ini` `batch_size = 1` и создайте текст заново — распознавание пойдёт медленнее, но привязка ко времени будет точнее.

### Что умеет режим чтения

-   Подсвечивает текущее слово, уже прозвучавшее приглушает.
-   Сам прокручивает страницу за озвучкой. Стоит прокрутить вручную — слежение приостанавливается на несколько секунд, чтобы не выдёргивать вас обратно. Совсем отключается галочкой «Следить за текстом».
-   Клик по любому слову перематывает воспроизведение на это место.
-   Позволяет подогнать подсветку под речь, если она спешит или отстаёт.
-   Запоминает выбранный режим: если вы ушли со страницы в режиме чтения, в нём же и вернётесь.

### Где лежит текст

Распознанный текст сохраняется **файлами рядом с аудио** — в подпапке `text/` внутри папки книги. На каждую аудиодорожку приходится два файла:

```
Аудиокниги/Ведьмак_Последнее_желание/
├── Глава_1.mp3
├── Глава_2.mp3
└── text/
    ├── Глава_1.txt      ← сплошной текст, можно открыть в любом редакторе
    ├── Глава_1.json     ← тот же текст + тайминги слов для подсветки
    ├── Глава_2.txt
    └── Глава_2.json
```

Зачем так, а не только в базе:

-   **Текст переживает сброс базы.** Если снова включить галочку, приложение подхватит готовые файлы за доли секунды вместо повторного распознавания.
-   **Книгу можно перенести целиком.** Скопировали папку на другой компьютер — текст поехал вместе с ней.
-   **Файлы можно править руками.** Распознавание ошибается; `.txt` открывается любым редактором. Подсветка берёт тайминги из `.json`, так что для неё правьте поле `t` внутри него.
-   **Можно принести свой текст.** Положите готовые `.json` в папку `text/` — при включении галочки они будут использованы как есть.

Снятие галочки в админке удаляет и записи в базе, и файлы с диска. Папка `text/` служебная: в каталоге книг она не показывается. Имя папки меняется переменной `CYBERAUDIO_TEXT_DIR`.

Если медиатека лежит на диске только для чтения, запись файлов пропускается с сообщением в консоли — текст всё равно сохранится в базе, и режим чтения будет работать.

### Поиск, порядок и свои папки

Над каталогом есть строка поиска: она ищет по всей медиатеке, а не только в открытой папке, так что помнить, в какой подпапке лежит книга, не нужно. Рядом — выбор порядка: по названию в обе стороны, «сначала недавние» и «меньше осталось». Папки при любой сортировке остаются наверху, иначе каталог стало бы неудобно обходить.

Вошедший читатель может собирать **свои папки** — подборки книг, которые видит только он. Кнопка со значком папки появляется на обложке книги, а сами подборки живут блоком «Мои папки» над каталогом. Книга при этом никуда не перемещается: подборка хранит только ссылку, поэтому одна книга может лежать сразу в нескольких. Гостям раздел не показывается.

### Скачивание книг

По умолчанию скачивание **выключено**. Включается галочкой «Разрешить скачивание» в админке, в разделе «Папки с музыкой».

Когда включено, у книги на обложке появляется значок загрузки — он отдаёт всю книгу одним архивом вместе с обложкой. В плеере такой же значок стоит у каждой главы и скачивает один файл. Клик по значку не запускает воспроизведение.

Архив собирается без сжатия: аудио уже сжато, и попытка ужать его только съела бы время и процессор. Пока архив отдаётся, он лежит во временной папке и удаляется сразу после отправки.

Когда галочка снята, значки пропадают, а прямые ссылки отвечают отказом — то есть выключение действительно закрывает доступ, а не просто прячет кнопки.

### Папки с музыкой на разных дисках

В админке есть раздел «Папки с музыкой». Основная папка лежит внутри приложения, и её путь можно изменить. Дополнительные подключаются с любого диска: указываете полный путь (`D:\Аудиокниги`, `/mnt/books`) и название — название становится разделом на главной странице.

Как это устроено внутри. Пути книг в основной папке остались прежними, без приставок, поэтому уже накопленные прогресс, расшифровки и подборки продолжают работать без переделки. Книги из дополнительных папок адресуются через её название: `Внешние/Классика/Война и мир`. Отсюда одно ограничение: название не должно совпадать с разделом внутри основной папки, иначе они перекрыли бы друг друга — приложение такое название не примет и объяснит почему.

Файлы из дополнительных папок отдаёт отдельный маршрут `/media`, потому что встроенная раздача Flask умеет работать только внутри папки приложения. Каждый запрос проверяется на принадлежность к подключённым папкам, так что вытянуть через него посторонний файл с диска нельзя.

Удаление папки из списка убирает её только из медиатеки — файлы на диске остаются на месте.

### Праздничное оформление

В админке есть раздел «Праздничное оформление» с галочками: Новый год, Хэллоуин, День всех влюблённых и весенний праздник.

У всех четырёх тем одна механика — цветная дымка поверх фона и дрейфующие светящиеся искры, — а сверх неё у каждой свой приём:

| Тема | Что происходит |
|---|---|
| Новый год | холодный синий свет, искры падают сверху, по краям обложек нарастает иней |
| Весенний праздник | тёплый свет сверху, пыльца поднимается снизу |
| День всех влюблённых | розовые искры вверх и толчки по краям экрана в ритме сердца: два удара и пауза |
| Хэллоуин | оранжево-фиолетовая гамма, раз в несколько секунд экран пересекает полоса помех, из-за края выглядывает глаз — клик по нему запускает ролик-скример |

Ролик для скримера задаётся там же, в настройках оформления, ссылкой на файл. Без неё глаз просто моргает и уходит обратно за край.

Тем можно включить несколько сразу — они складываются. Украшения рисуются отдельным слоем поверх страницы, который не перехватывает клики, так что карточки и кнопки работают как обычно. Ползунок плотности множит и число искр, и яркость дымки.

Если в системе включён режим уменьшенной анимации, остаются только цвета: ни искр, ни помех, ни пульса. Единственное исключение — глаз на Хэллоуин: он никуда не летит и не мигает, а без него пропал бы доступ к скримеру.

Ни картинок, ни эмодзи в оформлении больше нет, всё рисуется CSS-градиентами. Поэтому `static/assets/tentacles.svg` и `frost.svg`, оставшиеся от прежних щупалец и инея, ниоткуда не используются — их можно удалить.

### Дерево текстовых версий в админке

Раздел «Текстовые версии книг» повторяет структуру медиатеки: папки с вложенностью, книги — листьями. Переключатель «создать текст» есть на **каждом уровне**: включите его на папке, и в очередь встанут все книги внутри — не придётся протыкивать каждую по отдельности. На папке видно, сколько её книг уже с текстом, а частично заполненная ветка помечается промежуточным состоянием галочки.

Дерево обновляется само: пока идёт распознавание — каждые две секунды, в спокойном состоянии — раз в пятнадцать, так что книги, добавленные на диск со стороны, появляются без перезагрузки страницы. Раскрытые ветки при этом не схлопываются.

Читателям переключатель не виден вовсе: у них остаётся только кнопка «запросить текстовый формат» на самой книге.

### Если текста ещё нет: кнопка «запросить»

У книги без текста в плеере появляется кнопка с ладонью — «запросить текстовый формат». Она нужна, чтобы администратор понимал, какие книги читателям нужны в первую очередь, и не угадывал.

-   Нажать может только вошедший: гостю сначала откроется окно входа, ведь просьбу нужно к кому-то отнести.
-   Один человек просит одну книгу один раз — после нажатия кнопка гаснет и остаётся такой при следующих заходах.
-   Разные читатели просят независимо друг от друга, и админ видит список всех, кто просил.

Пока просьбы есть, у **всех** администраторов рядом с профилем висит сообщение «Запрошены текстовые книги» — на любой странице, а не только в админке. Клик по нему ведёт в панель.

В админке появляется раздел **«Запрошенные книги»**: книга, кто именно просил (ник и логин), дата первой просьбы. Оттуда же можно одной кнопкой поставить книгу в очередь на распознавание или убрать просьбы, если делать текст не планируется. Когда текст для книги включают, просьбы по ней снимаются автоматически, кнопка у читателей исчезает, а сообщение гаснет.

### Текстовые книги и озвучка

Папка, в которой лежит документ и нет ни одного аудиофайла, — **текстовая книга**. В медиатеке её не видно: слушателю там открывать нечего. Такие папки собраны в админке, в разделе **«Текстовые книги»** — путь, файл, размер и есть ли уже аудио.

Понимаются `pdf`, `docx`, `txt`, `md`, `fb2` и `epub`. У `pdf` должен быть текстовый слой: скан без распознавания воркер честно отвергнет с объяснением.

Соседний раздел **«Аудио версии книг»** устроен как «Текстовые версии книг», только в обратную сторону: там из аудио делали текст, здесь из документа делают аудио. Галочка ставит книгу в очередь, разбирает её тот же `worker/`.

Что происходит после галочки:

```
Компьютер с книгами                    Компьютер с моделями
(CyberAudio Hub)                       (worker/main.py)
        |                                      |
        |  1. галочка в админке -> очередь     |
        |<----- 2. «что озвучить?» ------------|
        |------ 3. книга и документ ---------->|
        |<----- 4. скачивает документ ---------|
        |                            5. достаёт текст,
        |                               режет на главы
        |------ 6. сколько глав <-------------|
        |                            7. наговаривает главу
        |<----- 8. mp3 главы ------------------|
        |<----- 9. текст главы с таймингами ---|
   10. кладёт файлы в папку книги
```

Главы приходят по одной, поэтому книгу можно начинать слушать, не дожидаясь конца: как только файл лёг в папку, она появляется в медиатеке как обычная аудиокнига.

**Текст идёт вместе с аудио.** При распознавании тайминги слов приблизительные — модель выравнивает их по звуку. При озвучке всё наоборот: воркер синтезирует речь кусками и точно знает длительность каждого. Поэтому у сгенерированной книги режим чтения работает сразу и попадает в слово точнее, чем у распознанной.

**Как режутся главы.** Сначала ищутся настоящие заголовки — строки вида «Глава 7», «Часть вторая», «Пролог», а в `docx` ещё и абзацы со стилем заголовка. Если их нет, книга делится по абзацам на куски примерно по `chapter_chars` знаков (по умолчанию около десяти минут звучания). Голая строка из цифр заголовком не считается: в `pdf` это чаще номер страницы, и книга разлетелась бы на сотни «глав».

**Снятие галочки удаляет созданное.** Стираются ровно те файлы, которые сделала озвучка, — они записаны в базе поимённо. Документ остаётся на месте, чужое аудио в папке не трогается.

Поставить в очередь папку, где уже есть аудио, нельзя: свои главы озвучка нумерует с единицы, и порядок перемешался бы. Сервер ответит об этом прямо в админке.

### Распознаватель на втором компьютере

Сам сервер речь **не распознаёт** и не требует для этого ни одной библиотеки: галочка в админке лишь ставит книгу в очередь. Разбирает очередь отдельная программа из папки `worker/`, запущенная на другом — обычно более мощном — компьютере. Так медиасервер может стоять на слабой машине, а Whisper работать там, где есть процессор посильнее или видеокарта.

Как это выглядит целиком:

```
Компьютер с книгами                    Компьютер с Whisper
(CyberAudio Hub)                       (worker/main.py)
        |                                      |
        |  1. галочка в админке -> очередь     |
        |<----- 2. «что распознать?» ----------|
        |------ 3. список глав --------------->|
        |<----- 4. скачивает аудио ------------|
        |                                 5. распознаёт
        |<----- 6. присылает текст ------------|
   7. кладёт в base и в text/*.txt
```

#### Запуск распознавателя

Скопируйте папку `worker/` на второй компьютер и выполните:

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate        # Linux / macOS
pip install -r requirements.txt
python main.py
```

Первый запуск создаст `config.ini` и остановится — впишите в него токен и адрес сервера, затем запустите `main.py` снова. Больше ничего настраивать не нужно.

Токен показан в админке в разделе «Текстовые версии книг» и печатается в консоли сервера при запуске. Задать свой можно переменной `CYBERAUDIO_WORKER_TOKEN`.

Модель Whisper скачивается при первом запуске (`large-v3` — около 3 ГБ) и дальше берётся с диска: интернет нужен ровно один раз. Распознавателей может быть несколько — главы разбираются по одной, и двое не возьмут одну и ту же.

Полезно знать: если распознаватель выключили посреди главы, она вернётся в очередь через 15 минут (`CYBERAUDIO_CLAIM_TIMEOUT`) и достанется следующему. Готовые главы не переделываются.

#### Работа на видеокарте

По умолчанию распознаватель настроен на `large-v3` и `device = cuda` — самую точную модель на видеокарте. Библиотеки CUDA ставятся прямо в виртуальное окружение вместе с остальными зависимостями, так что доустанавливать в систему ничего не нужно: хватает свежего драйвера NVIDIA. Нужны CUDA 12 и cuDNN 9.

**Про `compute_type` и карты RTX 50-й серии.** Обычно для экономии видеопамяти советуют `int8`, но на архитектуре Blackwell (RTX 5070/5080/5090, sm_120) CTranslate2 на нём падает с `CUBLAS_STATUS_NOT_SUPPORTED` — это известная несовместимость библиотеки. Поэтому по умолчанию стоит `float16`, и если в настройках окажется `int8`, распознаватель сам переключится на `float16` и напишет об этом в консоль. На скорости это почти не сказывается, а видеопамяти `large-v3` в `float16` занимает около 5 ГБ — на 16-гигабайтной карте запас более чем достаточный.

Скорость поднимает пакетная обработка: модель считает `batch_size` кусков записи разом и загружает карту полнее, чем при последовательном разборе. Для 16 ГБ разумно 16, для 8 ГБ — 8, для 24 ГБ — 24. Если увидите `CUDA out of memory`, уменьшите это число. Хотите ещё быстрее ценой точности — поставьте `beam_size = 1`.

Если видеокарты нет, а в настройках указано `cuda`, программа остановится с объяснением, а не уедет молча на процессор: `large-v3` на процессоре работает медленнее, чем идёт сама запись, и это было бы незаметной ловушкой.

Ориентир по скорости: на RTX 5080 `large-v3` в `float16` обрабатывает запись примерно в 20 раз быстрее реального времени — десятичасовая книга займёт около получаса. На процессоре та же книга считалась бы сутки с лишним.

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `[server] host`, `port` | Адрес сервера с книгами | `192.168.31.4:2077` |
| `[server] token` | Токен из админки | обязателен |
| `[worker] name` | Как машина подписывается в очереди | `worker` |

| `[whisper] model` | `tiny`, `base`, `small`, `medium`, `large-v3` | `large-v3` |
| `[whisper] device` | `cuda` (видеокарта NVIDIA) или `cpu` | `cuda` |
| `[whisper] compute_type` | `float16` для видеокарты, `int8` для процессора | `float16` |
| `[whisper] language` | Код языка, пусто — определять самому | `ru` |
| `[whisper] model_dir` | Куда качать модели | стандартный кеш |

Для сжатых форматов (mp3, m4a) на компьютере с распознавателем нужен **ffmpeg** — программа предупредит, если не найдёт его.

#### Какие задания брать

Воркер делает две работы, и обе управляются одним полем:

```ini
[worker]
; text  — распознавать аудио в текст (Whisper)
; voice — озвучивать книги из документов (синтез речи)
jobs = text, voice
```

Оставьте что-то одно — вторая модель не скачается и не займёт видеопамять. Whisper поднимается при старте, синтезатор — только когда придёт первая книга на озвучку.

#### Голос для озвучки

Движка три, выбирается полем `engine` в разделе `[tts]`.

**`f5ru` (по умолчанию)** — [F5-TTS_RUSSIAN](https://huggingface.co/Misha24-10/F5-TTS_RUSSIAN), дообученный на 5000 часах речи, из которых 4000 — русский датасет и ещё 400 часов русских аудиокниг. В отличие от многоязычных моделей русский для неё родной: нет акцента, правильные окончания, живая интонация. Своего голоса у модели нет — она повторяет тот, что дали в образце, вместе с манерой чтения. Скачивает около 1.4 ГБ при первом задании.

**`xtts`** — XTTS-v2 от Coqui. Голос красивый, но модель многоязычная и русского в обучении было мало: слышен акцент, ударения не расставляются вовсе. Оставлен как запасной.

**`silero`** — самый лёгкий: 50 МБ, идёт даже на процессоре, по-русски выговаривает чисто, но ровно, почти без эмоций. Образец голоса не нужен.

##### Образец голоса

`f5ru` требует `speaker_wav` — чистую запись на 6–15 секунд. Проще всего взять кусок любой аудиокниги из вашей же медиатеки: чей голос дадите, тот и будет читать.

```bash
ffmpeg -ss 90 -t 11 -i "путь/к/книге/01.mp3" -ac 1 -ar 24000 voice.wav
```

Чем живее прочитан образец, тем живее выйдет книга: модель копирует не только тембр, но и темп, паузы, эмоциональную окраску. Ровный дикторский образец даст ровное чтение, а выразительный — выразительное.

Что говорят в образце, знать тоже нужно — модель сверяет запись с текстом. Поле `speaker_text` можно оставить пустым: воркер расшифрует образец тем самым Whisper, который у него уже стоит. Заполнять вручную стоит, только если распознавание отключено (`jobs = voice`).

##### Ударения

Русский синтез спотыкается не на тембре, а на ударениях: **з**а́мок или зам**о́**к понятно только по смыслу фразы. `f5ru` умеет принимать разметку, а расставляет её [RUAccent](https://github.com/Den4ikAI/ruaccent) — отдельная небольшая модель, включена по умолчанию (`accent = yes`). В текст, который уходит в режим чтения, служебные знаки не попадают.

##### Лицензии

И `f5ru` (CC BY-NC 4.0), и `xtts` (Coqui CPML) — некоммерческие: пользоваться бесплатно можно, продавать полученную озвучку нельзя. Пока в настройках `accept_license = no`, воркер за озвучку не возьмётся и напишет об этом в консоль. `silero` этого не требует.

| Параметр `[tts]` | Назначение | По умолчанию |
|---|---|---|
| `engine` | `f5ru`, `xtts` или `silero` | `f5ru` |
| `checkpoint` | Версия весов `f5ru`: `v2`, `v4`, `accent`, `v1` | `v2` |
| `accept_license` | Согласие с лицензией. Без него озвучка не запустится | `no` |
| `device` | `cuda` или `cpu` | `cuda` |
| `speaker_wav` | Образец голоса. Для `f5ru` обязателен | пусто |
| `speaker_text` | Что говорят в образце. Пусто — расшифруем сами | пусто |
| `speaker` | Имя голоса для `xtts` / `silero` | пусто |
| `accent` | Расставлять ударения через RUAccent (только `f5ru`) | `yes` |
| `accent_model` | `turbo3.1` или `big_poetry` | `turbo3.1` |
| `nfe_step` | Шагов на кусок у `f5ru`: больше — чище и медленнее | `32` |
| `language` | Язык текста | `ru` |
| `speed` | Темп речи | `1.0` |
| `model_dir` | Куда качать модели | стандартный кеш |
| `chapter_chars` | Длина главы в знаках, если заголовков в книге нет | `9000` |
| `bitrate` | Битрейт готовых mp3 | `64k` |

**Про torch и видеокарту.** `coqui-tts` тянет за собой torch, а `pip` по умолчанию ставит сборку без CUDA — озвучка тогда пойдёт на процессоре и будет медленнее раз в двадцать. Поставьте torch первым, с индекса NVIDIA:

```bash
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
python -c "import torch; print(torch.cuda.is_available(), torch.version.cuda)"
python -c "from TTS.api import TTS; print('XTTS готов')"
```

`torchaudio` обязателен — XTTS импортирует его у себя внутри, и без него озвучка не поднимется. Ставьте его той же командой, что и torch: с PyPI приедет сборка без CUDA и потянет за собой второй, процессорный torch.

Ещё два пакета закреплены в `requirements.txt` не просто так, и снимать ограничения не стоит:

-   **`transformers>=4.57,<5`.** Сам `coqui-tts` просит `transformers>=4.57` без верхней границы, поэтому `pip` тянет пятую ветку. В ней убрали `transformers.pytorch_utils.isin_mps_friendly`, и импорт XTTS падает на этой строке.
-   **`torchcodec>=0.8`.** Начиная с torch 2.9 `coqui-tts` работает со звуком через него и без него отказывается импортироваться вовсе.

Проверить, что цепочка собралась целиком, можно одной командой — она поднимает ровно то, что потом поднимет воркер:

```bash
python -c "from TTS.api import TTS; print('XTTS готов')"
```

Индекс именно `cu128`. Причин две, и каждой хватает по отдельности:

-   Карты **50-й серии** (RTX 5070/5080/5090, архитектура Blackwell, `sm_120`) вышли позже CUDA 12.1, и в сборках `cu121` для них нет скомпилированных ядер. Ровно та же история, что с `int8` в CTranslate2.
-   Индекс `cu121` заморожен: последний torch там — 2.5 под Python не старше 3.12. На свежем Python `pip` отвечает `No matching distribution found for torch`, и это не сбой сети, а честное «под вашу версию колёс нет».

Для карт 40-й серии и старше подойдёт и `cu126`, но `cu128` работает и там.

На распознавание речи это не влияет: `faster-whisper` работает через CTranslate2, и torch ему не нужен вовсе. Но torch принесёт свои версии `nvidia-cublas-cu12` и `nvidia-cudnn-cu12`, поэтому после установки запустите `main.py` один раз и убедитесь, что распознавание тоже поднялось.

### Настройки сервера через переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `CYBERAUDIO_WORKER_TOKEN` | Токен доступа для распознавателей | создаётся сам |
| `CYBERAUDIO_CLAIM_TIMEOUT` | Через сколько минут брошенная глава вернётся в очередь | `15` |
| `CYBERAUDIO_TEXT_DIR` | Имя папки с текстом рядом с аудио | `text` |
| `CYBERAUDIO_DEBUG` | Режим отладки Flask. `0` — выключить | `1` |

### О времени работы

Скорость зависит от того, где считает распознаватель: на видеокарте `large-v3` идёт в разы быстрее записи, на процессоре — в разы медленнее. Поэтому:

-   Очередь разбирается по главам, и готовая глава сохраняется сразу — перезапуск любой из машин не теряет работу.
-   Читать можно, не дожидаясь всей книги: главы открываются по мере готовности.
-   Если видеокарты нет, поставьте `device = cpu`, `compute_type = int8` и модель поменьше (`small` или `base`) — иначе ждать придётся очень долго.

Снятый переключатель удаляет текст книги и из базы, и с диска, а также снимает её с очереди.

### Если открываете доступ по сети

Для постоянной работы режим отладки лучше выключить — он даёт интерактивную консоль Python всякому, кто дотянется до порта:

```bash
CYBERAUDIO_DEBUG=0 python app.py
```
