# Приложение CyberAudio Hub для Android

Полка с книгами, иерархия папок как на сайте, вход в тот же аккаунт,
прослушивание, скачивание на телефон и виджет плеера на экране блокировки.

## Почему нативное, а не Kivy

Рядом лежит черновик на Kivy (`application/main.py` и соседние файлы). Он
собирается только через Buildozer, а тот работает исключительно под Linux —
под Windows его нет вовсе. На машине, где всё это писалось, стоит Android SDK
из Visual Studio и Windows без WSL, поэтому собрать тот черновик было
физически нечем.

Второе, менее очевидное: в Kivy не сделать нормальные кнопки в виджете
плеера. Нажатия приходят в `MediaSessionCompat.Callback` — абстрактный класс,
а pyjnius умеет наследовать только интерфейсы. Пришлось бы писать прослойку
на Java, то есть всё равно частично уходить в нативный код.

Черновик оставлен на месте: он показывает задумку и формат контейнера.

## Сборка

Нужны JDK 17+ и Android SDK с платформой 35 и build-tools 36.

```bash
cd application/android
gradle assembleDebug
```

Готовый файл — `app/build/outputs/apk/debug/app-debug.apk`. Скопируйте его
в `application/` под именем `CyberAudioHub.apk`, и сайт начнёт отдавать его
по кнопке «Скачать приложение на Android» в окне профиля.

Если Gradle в системе нет, скачайте дистрибутив с gradle.org и запускайте
`gradle.bat` оттуда — обёртки в репозитории нет намеренно, чтобы не хранить
бинарный `gradle-wrapper.jar`.

Путь к SDK берётся из `local.properties`. Файл машинно-зависимый, в
репозиторий не попадает; создайте свой:

```properties
sdk.dir=C:/Program Files (x86)/Android/android-sdk
```

## Что внутри

| Файл | Назначение |
|---|---|
| `MainActivity` | Адрес сервера, вход и регистрация |
| `ShelfActivity` | Полка: папки и книги, плюс список скачанного |
| `PlayerActivity` | Плеер, список глав, скачивание |
| `PlaybackService` | Воспроизведение, MediaSession, виджет в шторке |
| `Api` | Запросы к серверу на голом HttpURLConnection |
| `Container` | Формат `.cah`: упаковка и чтение |
| `ContainerDataSource` | Расшифровка скачанной книги на лету при игре |
| `Store` | Список скачанных книг и позиция прослушивания |
| `Ui` | Оформление под сайт: цвета, кнопки, поля |

## Виджет на экране блокировки

Он появляется не сам по себе — нужны три вещи разом:

1. `MediaSession` с метаданными и состоянием воспроизведения;
2. уведомление со стилем `MediaStyle`, ссылающееся на токен этой сессии;
3. служба на переднем плане (`foregroundServiceType="mediaPlayback"`).

Уберите любую из трёх — и в шторке останется просто строчка текста, а на
заблокированном экране не будет ничего. С Android 13 к этому добавляется
разрешение `POST_NOTIFICATIONS`: приложение спрашивает его при первом
открытии плеера.

## Формат .cah

Скачанная книга лежит не обычным mp3, а контейнером, который не открывается
сторонним плеером:

```
"CAH1" | длина заголовка, 4 байта big-endian | JSON | звук, наложенный потоком
```

Поток — SHA-256 по номеру блока, блок 32 байта. Наложение симметричное и
учитывает смещение, поэтому перемотка в середину главы расшифровывается
правильно, а файл не приходится разворачивать целиком.

**Честно о степени защиты:** это заслон от случайного открытия, а не от
специалиста. Ключ лежит внутри приложения, и тот, кто захочет, достанет
исходный звук. Настоящая защита потребовала бы выдачи ключей сервером и
полноценного DRM, чего здесь нет.

Формат совпадает с реализацией на Python (`application/backend.py`) байт в
байт — это проверяется тестами.

## Тесты

```bash
gradle testDebugUnitTest
```

Шесть проверок контейнера, гоняются на обычной JVM, без телефона и
эмулятора. Эталонные значения посчитаны реализацией на Python: если поток
шифрования разойдётся, книга, скачанная одной версией, перестанет читаться
другой. Отдельно проверяется шифрование со смещением — если сломается оно,
звук после перемотки превратится в шум, а на слух это поймать трудно.

## Чего ещё не было

Ни один экран не запускался на устройстве. Собирается и проходит тесты —
но как приложение выглядит и ведёт себя на телефоне, пока не проверено.
